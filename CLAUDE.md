## Architecture

- Server Components by default. Put `"use client"` on the smallest leaf that needs state, effects, event handlers or browser APIs, and pass server data down as props.
- Server-only code (data access, secrets, file system) lives in `src/server/` and starts with `import "server-only"`.
- Cache Components are on: cache with `"use cache"` plus `cacheLife()` / `cacheTag()` inside a helper function. Do not add `export const dynamic` or `revalidate` route segment config.
- Next.js 16.4 specifics: `error.tsx` receives `{ error: unknown; retry }`, so narrow `error` before use; `PageProps<"/route">` and `LayoutProps<"/route">` are global types generated by `next typegen`; `next lint` no longer exists.

## Structure

```text
src/
  app/          routes and Next.js file conventions (layout, page, loading, error, not-found, route)
  components/   feature components; ui/ is generated by shadcn (`npx shadcn@latest add <name>`)
  hooks/        reusable client hooks (`use-*.ts`)
  lib/          framework-agnostic helpers (`utils.ts` for `cn`, `site-config.ts`)
  server/       server-only modules
  env.ts        validated environment variables
public/         static files served from `/`
```

## Environment variables

- Read env only through `env` from `@/env`, never `process.env` directly.
- New variable: add it to the server or client schema in `src/env.ts`, document it in `.env.example`, put the real value in `.env.local` (git-ignored), in the Vercel project settings and in CI (`env:` of the `check` job in `.github/workflows/ci.yml`, secrets via `${{ secrets.NAME }}`). `next build` prerenders `/` and validates the schema, so a required variable missing in CI fails the build.
- Client variables must start with `NEXT_PUBLIC_` and must also be listed in `clientValues` in `src/env.ts`: Next.js inlines only literal `process.env.NEXT_PUBLIC_*` reads.
- `.env` and `.env.*` (except `.env.example`) are denied to Claude in `.claude/settings.json`; never ask to print them.

## Code style

- Components and types: PascalCase. Variables, functions and hooks: camelCase (`useCopyToClipboard`).
- File names: kebab-case (`copy-command.tsx`, `use-copy-to-clipboard.ts`), including route folders (`app/user-settings/`).
- Named exports only, except where Next.js requires a default export (`page`, `layout`, `loading`, `error`, `not-found`, `template`, `default`, `next.config.ts`).
- No `any`: use `unknown` and narrow it (type guards, zod). Handle the `undefined` that `noUncheckedIndexedAccess` adds instead of silencing it with `!`.
- Import through the `@/` alias. Prettier owns formatting.
- Tests sit next to the code as `*.test.tsx`. Vitest globals are off: import `describe`, `it`, `expect` from `vitest`. Async Server Components cannot be unit-tested with Vitest; cover them with end-to-end tests. `server-only` is aliased to a no-op in Vitest, but `"use cache"` / `cacheLife()` only work inside Next.js, so keep testable logic in plain functions.

## Commands

```bash
npm run dev               # dev server on http://localhost:3000
npm run lint              # ESLint; lint:fix to autofix
npm run typecheck         # next typegen && tsc --noEmit
npm run test              # Vitest once; test:watch for watch mode
npm run format            # Prettier write; format:check only verifies (run by check and CI)
npm run check             # lint, format:check, typecheck, test, build in sequence
```

Before every commit, run `npm run check` and make sure it passes.

## Accessibility (required)

- Semantic HTML first: landmarks (`main`, `header`, `nav`), one `h1` per page, real `<button>` and `<a>`, labelled form fields.
- Every interactive element shows `cursor: pointer` (global CSS covers `button` and `[role="button"]`) and a visible `:focus-visible` style. Never remove an outline without a replacement.
- Every image has `alt` (`alt=""` only for decorative images); decorative icons get `aria-hidden="true"`.
- Contrast meets WCAG AA (4.5:1 for text, 3:1 for large text and UI boundaries); use theme tokens such as `text-foreground` and `text-muted-foreground`.
- Announce async results with `role="status"` instead of moving focus.
